# 领域论文自动检索、Zotero 归档与结构化解读 Skill

## 1. Skill 目标

该 Skill 用于自动完成指定研究领域的论文调研流程：

1. 先询问用户要检索的研究领域、关键词或任务方向。
2. 检索该领域最新、最相关的顶刊顶会论文。
3. 筛选 **5 篇**满足条件的论文：
   - 与用户输入领域高度相关；
   - 优先最新年份，例如优先 2026，其次 2025，再往前；
   - 优先顶刊顶会；
   - 必须有可下载 PDF；
   - 必须有开源代码链接；
   - 代码尽量具备可复现条件；
   - **不得与 Zotero 中已有论文重复**。
4. 在 Zotero 中创建一个新集合。
5. 新集合命名方式为当天日期，格式为：`YYYY-MM-DD`。
6. 将 5 篇论文 PDF 导入该 Zotero 新集合。
7. 只保留论文 PDF 和对应 Markdown 解读文件。
8. 不保留网页快照、HTML 页面、无关附件或重复 PDF。
9. 不做全文翻译。
10. 对每篇论文生成一个结构化 Markdown 解读文件。
11. 每篇 Markdown 解读文件开头必须包含该论文的开源代码链接。
12. 每篇论文必须额外包含“主要图表大白话讲解”部分。
13. 每篇论文必须明确列出使用的数据集，包括训练集、验证集、测试集、主实验数据集和消融实验数据集；如果论文未说明，必须写“论文未明确说明，不能确定”。
14. 每篇论文必须给出发表源等级，包括 CCF 等级、中科院分区、JCR 分区或会议/期刊等级；如果无法从可靠来源确认，必须写“未能可靠确认”。
15. 最终按照“优先阅读价值 + 优先复现价值”排序。
14. 必须生成 `00_论文优先级总览.md`。
15. 必须执行 Markdown 解读文件完整性自检，禁止生成简版摘要。

## 2. 触发条件

当用户表达以下意图时，触发该 Skill：

- “帮我找某个领域的论文”
- “帮我检索最新论文”
- “帮我找 5 篇可复现论文”
- “帮我整理到 Zotero”
- “帮我做一个领域论文调研”
- “帮我找顶刊顶会开源论文”
- “帮我自动下载论文并生成解读”
- “调用论文检索 Zotero 归档 skill”

如果用户没有明确领域，必须先询问领域。

---

## 3. 首轮必须询问用户的问题

触发 Skill 后，必须先问：

> 你要检索哪个研究领域 / 关键词 / 任务方向？  
> 例如：组合图像检索 CIR、细粒度跨模态检索、文本图像检索、图像编辑检索、多模态检索、视觉语言模型等。

如果用户已经给出领域，则不再重复询问，直接执行检索。

可选补充问题，但不要强制用户回答：

- 是否只要近两年论文？
- 是否限定会议或期刊？
- 是否只要代码完整可运行的论文？
- 是否优先适合复现？
- 是否优先适合写 Related Work？
- 是否排除 arXiv-only 论文？

如果用户没有回答可选问题，使用默认策略。

## 4. 默认策略

如果用户没有额外说明，采用以下默认设置：

- 论文数量：5 篇；
- 年份优先级：2026 > 2025 > 2024 > 2023；
- 类型优先级：
  1. 顶会 / 顶刊正式发表；
  2. 顶会 workshop，但方法和代码质量较高；
  3. arXiv-only，但必须有强相关性和高质量代码；
- 代码要求：
  - 必须有 GitHub / 官方代码仓库 / Papers with Code 代码链接；
  - 优先选择有 README、requirements、训练脚本、评估脚本、模型权重或复现实验说明的论文；
- 文件要求：
  - 必须有 PDF；
  - Zotero 中只保留 PDF 和 `.md` 解读文件；
- 翻译要求：
  - 不生成全文翻译；
  - 改为讲解论文主要图表；
- 去重要求：
  - 如果 Zotero 中已有同一论文，则跳过；
  - 如果候选结果与本次已入选论文重复，也跳过；
  - 不得为了凑数重复导入同一论文；
- 排序依据：
  - 领域相关性；
  - 发表质量；
  - 年份新旧；
  - 代码可复现程度；
  - 方法创新性；
  - 实验严谨性；
  - 是否适合优先阅读；
  - 是否适合优先复现。

## 7. 论文筛选规则

### 7.1 必须满足的条件

每篇论文必须满足：

- 与用户输入领域高度相关；
- 有 PDF；
- 有开源代码；
- 代码仓库可访问；
- 论文来自顶刊 / 顶会 / 高质量预印本；
- 内容适合后续阅读、复现或写论文参考；
- **不与 Zotero 已有条目重复**；
- **不与本次入选论文重复**。

### 7.2 优先级评分

为每篇候选论文打分，满分 100 分：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 领域相关性 | 25 | 是否精准匹配用户输入方向 |
| 发表质量 | 20 | 顶会 / 顶刊优先 |
| 年份新旧 | 15 | 越新越优先 |
| 代码可复现性 | 20 | README、环境、脚本、权重是否完整 |
| 方法创新性 | 10 | 是否有明确方法贡献 |
| 实验严谨性 | 10 | 是否有强基线、消融、多数据集 |
| 数据集信息完整性 | 加权参考 | 是否明确报告训练、验证、测试和消融数据集 |
| 等级可信度 | 加权参考 | CCF / 中科院 / JCR 信息是否可可靠确认 |

最终选择总分最高且不重复的 5 篇。

### 7.3 代码可复现性等级

每篇论文必须判断代码可复现性：

| 等级 | 判断标准 |
|---|---|
| 高 | 有 README、环境配置、训练脚本、评估脚本、数据说明、权重或日志 |
| 中 | 有主要代码和 README，但缺少部分复现细节 |
| 低 | 代码不完整、缺少训练脚本或环境配置 |
| 不确定 | 仓库存在但无法确认是否可运行 |

如果代码只是占位仓库，不能视为开源可复现论文。

## 8. Zotero 查重与归档规则

### 8.1 新集合命名

在 Zotero 中创建新集合：

```text
YYYY-MM-DD
```

示例：

```text
2026-06-05
```

如果当天已存在同名集合，则创建：

```text
YYYY-MM-DD_领域关键词
```

示例：

```text
2026-06-05_CIR
```

如果仍然重名，则追加序号：

```text
2026-06-05_CIR_02
```

### 8.2 导入前必须查重

在导入每篇论文前，必须在 Zotero 全库中查重，不仅检查当天新集合。

查重字段优先级如下：

1. DOI；
2. arXiv ID；
3. OpenReview ID；
4. 标题标准化匹配；
5. PDF URL；
6. 代码仓库 URL；
7. 第一作者 + 年份 + 标题关键词。

标题标准化匹配规则：

- 全部转小写；
- 去除标点；
- 去除多余空格；
- 去除冒号、副标题分隔符差异；
- 忽略大小写和连字符差异。

### 8.3 已有论文处理规则

如果发现 Zotero 中已经存在同一论文：

- 不再下载 PDF；
- 不再导入 Zotero；
- 不再生成重复 md；
- 不计入最终 5 篇；
- 在 `00_论文优先级总览.md` 的“已存在而跳过的论文”表中记录；
- 继续检索下一篇候选论文补足 5 篇。

记录格式：

| 论文标题 | 年份 | 已存在位置 / 集合 | 跳过原因 |
|---|---|---|---|

### 8.4 本次候选去重

如果不同来源返回同一论文，例如 arXiv、OpenReview、会议页面、Papers with Code 同时出现：

- 合并为同一候选条目；
- 保留最权威 PDF 链接；
- 保留最完整代码链接；
- 只生成一个 PDF 和一个 md；
- 不重复计数。

### 8.5 Zotero 集合内容

集合中每篇论文保留：

```text
01_论文标题.pdf
01_论文标题_解读.md

02_论文标题.pdf
02_论文标题_解读.md

03_论文标题.pdf
03_论文标题_解读.md

04_论文标题.pdf
04_论文标题_解读.md

05_论文标题.pdf
05_论文标题_解读.md
```

### 8.6 文件命名规则

文件名必须统一：

```text
序号_第一作者姓氏_年份_论文短标题.pdf
序号_第一作者姓氏_年份_论文短标题_解读.md
```

示例：

```text
01_Liu_2026_Composed_Image_Retrieval.pdf
01_Liu_2026_Composed_Image_Retrieval_解读.md
```

要求：

- 序号使用两位数字：`01` 到 `05`；
- 文件名中不要使用特殊符号；
- 空格替换为下划线；
- 标题过长时截断为核心短标题；
- PDF 和 Markdown 解读文件必须同序号、同前缀；
- 排序必须体现优先阅读和复现价值。

### 8.7 附件清理规则

导入 Zotero 后必须清理：

- 删除网页快照；
- 删除 HTML；
- 删除重复 PDF；
- 删除无关图片；
- 删除自动保存的网页附件；
- 保留论文 PDF；
- 保留对应 Markdown 解读文件；
- 保留 `00_论文优先级总览.md`。

## 9. 每篇论文解读 Markdown 文件硬性要求

每篇论文必须生成一个 `.md` 文件。  
文件最开头必须包含论文资源链接，尤其是开源代码链接。

**禁止生成简版摘要。**  
**禁止只输出“一句话概括 / 核心方法 / 复现建议”。**  
**禁止省略 Backbone / Framework / Module 拆解。**  
**禁止省略实验公平性、调参分析、投稿风险评估和最终评级。**

每篇论文的 `{序号}_{作者}_{年份}_{短标题}_解读.md` 必须完整包含以下 10 个一级章节，章节标题必须逐字一致，不允许省略、不允许合并、不允许改名：

1. `## 0. 论文资源链接`
2. `## 一、核心结论速览`
3. `## 二、模型结构严格拆解`
4. `## 三、实验基线与严谨性`
5. `## 四、调参情况：是否存在暴力刷分`
6. `## 五、核心性能提升`
7. `## 六、主要图表大白话讲解`
8. `## 七、论文局限性与可借鉴价值`
9. `## 八、投稿风险评估`
10. `## 九、最终可用性评级`

如果论文没有提供某项信息，必须保留对应小节、表格和字段，并填写：

```text
论文未明确说明，不能确定。
```

## 12. 异常处理规则

### 12.1 找不到 5 篇满足条件的论文

如果无法找到 5 篇同时满足“顶刊顶会 + PDF + 开源代码 + 高相关性 + Zotero 未重复”的论文，则按以下顺序放宽：

1. 保留高相关性和开源代码，放宽会议等级；
2. 保留顶刊顶会和高相关性，接受代码复现性较弱；
3. 接受高质量 arXiv-only，但必须有代码；
4. 最终不足 5 篇时，明确说明不足原因。

不能为了凑数加入弱相关论文。  
不能为了凑数重复导入 Zotero 中已有论文。

### 12.2 代码链接失效

如果代码链接失效：

- 标记为“代码不可访问”；
- 不优先入选；
- 如果论文非常重要，可以列入“不入选但值得关注”；
- 不得声称代码可复现。

### 12.3 PDF 无法下载

如果 PDF 无法下载：

- 尝试从 arXiv、作者主页、会议页面寻找备用 PDF；
- 如果仍无法下载，不导入 Zotero；
- 可列入“不入选但值得关注”；
- 不计入最终 5 篇。

### 12.4 Zotero 写入失败

如果无法写入 Zotero：

- 明确报告失败原因；
- 保留本地文件夹结构；
- 文件夹命名与 Zotero 集合一致；
- 提供后续手动导入 Zotero 的说明；
- 不得假装已经成功导入 Zotero。

### 12.5 图表无法解析

如果无法读取 PDF 中的图表：

- 明确写“该图表无法解析”；
- 不要凭空解释图表；
- 只基于论文正文对图表的描述进行说明；
- 如果正文也没有说明，写“论文未明确说明，不能确定”。

### 12.6 Markdown 解读文件不完整

如果生成的 `_解读.md` 缺少任意必需章节：

- 不得保存该文件；
- 必须重新生成；
- 如果连续两次生成失败，必须向用户报告失败原因；
- 不得用简版摘要替代完整解读。

### 12.7 Zotero 中已有论文

如果某篇论文已存在于 Zotero：

- 必须跳过；
- 不得重复导入；
- 不得重复生成 md；
- 在 `00_论文优先级总览.md` 中记录；
- 必须继续检索下一篇候选论文补足 5 篇。

## 13. 强制约束

执行 Skill 时必须遵守以下规则：

1. 必须先明确用户要检索的领域。
2. 最终入选论文数量固定为 5 篇。
3. 每篇论文必须有 PDF。
4. 每篇论文必须有开源代码链接。
5. 每篇论文必须生成对应 Markdown 解读文件。
6. Markdown 解读文件开头必须包含开源代码链接。
7. 不生成全文翻译。
8. 必须讲解主要图表，且用大白话说明。
9. 必须创建 Zotero 新集合。
10. Zotero 新集合命名必须基于当天日期。
11. Zotero 中只保留 PDF 和 Markdown 解读文件。
12. 必须按照优先阅读和优先复现价值排序。
13. 所有论文解读必须基于论文原文和实验结果。
14. 不允许主观臆测论文贡献。
15. 不允许把 Backbone、Framework、Module 混为一谈。
16. 如果论文存在刷分、弱基线、不公平对比、无多 seed、代码不完整等问题，必须直接指出。
17. 不允许为了凑够 5 篇加入弱相关论文。
18. 如果 Zotero 操作失败，必须明确说明。
19. 最终必须生成 `00_论文优先级总览.md`。
20. 最终输出必须说明 Zotero 集合名称和每篇论文的文件名。
21. **不得导入 Zotero 中已有论文。**
22. **不得重复导入同一论文的不同版本。**
23. **不得生成简版 `_解读.md`。**
24. **每篇 `_解读.md` 必须完整包含 10 个固定一级章节。**
25. **生成后必须执行 Markdown 解读文件自检。**
26. **如果自检失败，必须重新生成。**
27. **每篇论文必须给出使用的数据集及其用途。**
28. **每篇论文必须给出 CCF 等级；若是期刊，还必须尽量给出中科院分区和 JCR 分区。**
29. **等级信息必须来自可靠来源；无法确认时必须写“未能可靠确认”，不得编造。**
